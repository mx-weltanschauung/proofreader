# Помощник для вычитки главы

Помощник запускается на вашем компьютере и отправляет текст полос выбранной вами модели. Вы сверяете её находки со сканами на сайте и решаете, какие исправления передать модератору.

## Установка

1. Откройте [успешные сборки основной ветки](https://github.com/mx-weltanschauung/proofreader/actions/workflows/ci.yml?query=branch%3Amain+is%3Asuccess), выберите последнюю сборку с артефактами `proofread-assist`. Для скачивания артефактов GitHub нужен вход в аккаунт.
2. Внизу страницы в **Artifacts** скачайте архив для своей системы и архитектуры. Доступны Windows x64, Linux x64 и macOS на Apple Silicon. Распакуйте ZIP от GitHub, затем вложенный архив с номером версии. На Linux и macOS команда `tar -xzf имя-архива.tar.gz` сохраняет право запуска.
3. Откройте терминал в папке с программой. Проверьте версию командой `.\proofread-assist.exe --version` в Windows PowerShell или `./proofread-assist --version` в Linux и macOS. Python и Tesseract для обычного анализа не требуются.

После обновления помощника скачайте новый архив и замените исполняемый файл на своём компьютере: обновление сайта само программу не обновляет.

## Работа с главой

1. Выберите способ анализа: OpenAI-совместимый сервер, Codex CLI, Claude Code CLI или Anthropic API. Для сервера подготовьте адрес и имя модели. Подходит локальный сервер (например, `http://localhost:8080/v1`) или внешний сервис, которому вы доверяете текст. Если сервис требует ключ, задайте переменную окружения `OPENAI_API_KEY` в терминале, из которого запускаете программу. Для удалённой модели с ключом используйте HTTPS.
2. Войдите на сайт как читатель. Откройте работу над главой, раскройте **Подключить помощник для анализа** и нажмите **Получить одноразовый код**. Выполните показанную команду `pair` с адресом вашего сайта. Если программа лежит в текущей папке, замените начало команды `proofread-assist` на `.\proofread-assist.exe` в Windows или `./proofread-assist` в Linux и macOS.
3. Для OpenAI-совместимого сервера один раз выполните команду `configure` из работы, подставив адрес API вместо `URL` и имя модели вместо `MODEL`. Помощник пошлёт модели короткую тестовую фразу и сохранит адрес и имя после успешного ответа. Затем запустите показанную команду `run` с номером работы. Для CLI или Anthropic API используйте варианты ниже. При обрыве повторите `run`: помощник продолжит с необработанных полос.
4. Обновите работу на сайте. Для каждой находки сравните исходный текст и замену со сканом, примите или отклоните правку. Проверьте итоговый текст полос и подтвердите отправку в модерацию.

### Локальная Qwen через Ollama

Установите [Ollama](https://ollama.com/download) и загрузите модель с поддержкой изображений, например [Qwen 3.5 4B](https://ollama.com/library/qwen3.5):

```sh
ollama pull qwen3.5:4b
```

Убедитесь, что локальный сервер Ollama запущен. После команды `pair` из работы на сайте настройте модель и запустите анализ (замените `proofread-assist` на путь к скачанной программе):

```sh
proofread-assist configure НОМЕР_РАБОТЫ --model-url http://127.0.0.1:11434/v1 --model qwen3.5:4b
proofread-assist run НОМЕР_РАБОТЫ --vision
```

`--vision` передаёт скан модели; без него она видит только Markdown. Для локального Ollama ключ `OPENAI_API_KEY` не нужен: если он задан в терминале для другого сервиса, удалите его перед запуском (`unset OPENAI_API_KEY` в Linux/macOS или `Remove-Item Env:OPENAI_API_KEY` в PowerShell). Помощник требует от модели JSON с точными позициями правок. `configure` проверяет формат отдельной полосы на коротком запросе; пакетный формат проверяется при `run`. Работа Qwen с реальными полосами, качество правок и координат выделения на скане пока не проверены. Если модель не вернёт координаты, находку всё равно можно сверить по полной странице.

### Через Codex CLI без ключа API

Установите [Codex CLI](https://developers.openai.com/codex/cli), войдите через свой аккаунт ChatGPT и проверьте вход командой `codex login status`. Затем выполните `proofread-assist run НОМЕР_РАБОТЫ --codex --vision` вместо `configure` и обычного `run`. Флаг `--vision` передаст Codex скан, чтобы он мог указать место находки; без этого флага прямоугольники не появятся. Если модель не может уверенно найти место на скане, находка останется без прямоугольника и её нужно сверить по полной странице. Codex запускается в пустом временном каталоге с доступом только на чтение; ключ API и токен сайта ему не передаются. Используется лимит вашего плана Codex. Чтобы сравнить с другим способом анализа, нажмите на сайте **Новая проверка главы**: уже обработанные полосы помощник повторно не отправляет.

### Через Claude Code CLI без ключа API

Установите [Claude Code](https://code.claude.com/docs/en/overview), войдите через свой аккаунт и проверьте вход командой `claude auth status`. Затем запустите:

```sh
proofread-assist run НОМЕР_РАБОТЫ --claude --vision
```

`--model ИМЯ` выбирает модель Claude Code; без этого флага используется её настройка по умолчанию. Помощник запускает Claude Code в безопасном режиме без инструментов и не передаёт ему ключ API или токен сайта.

### Через Anthropic API

Задайте `ANTHROPIC_API_KEY` в терминале и выберите доступную вашему аккаунту модель:

```sh
proofread-assist run НОМЕР_РАБОТЫ --claude-api --model ИМЯ_МОДЕЛИ --vision
```

Используется [Anthropic Messages API](https://platform.claude.com/docs/en/api/messages). Этот путь оплачивается отдельно по тарифу API. Ключ отправляется только на `api.anthropic.com`; сайту он не передаётся.

### Размер пакета

`run` отправляет модели до 10 полос за один вызов. Волонтёр может изменить размер пакета флагом `--batch-size N`, где `N` от 1 до 20. Например, `proofread-assist run НОМЕР_РАБОТЫ --claude --vision --batch-size 15`. Для локальной модели с небольшим контекстом уменьшите число, вплоть до `--batch-size 1`. Помощник также разделяет пакет, если текст или сканы слишком велики, и повторяет анализ меньшими группами при ошибке ответа. Результаты сохраняются отдельно для каждой полосы; повторный `run` продолжит с незавершённых.

По умолчанию модель получает только текст. Флаг `--vision` добавляет скан к запросу и требует модель с поддержкой изображений. Для дополнительного локального распознавания установите Tesseract, добавьте его в PATH и установите языковые данные. Флаг `--ocr` включает распознавание, `--ocr-language rus` выбирает русский язык. Ключ API передаётся модели. Для сайта помощник хранит отдельный токен работы в каталоге конфигурации пользователя.

## Сборка и сквозной тест для разработчика

В каталоге помощника установите зависимости сборки и запустите:

```sh
python -m pip install pytest certifi pyinstaller==6.16.0
python -m pytest -q
python packaging/build.py
```

Исполняемый файл и архив для текущей ОС появятся в `dist/`. Для сквозной проверки на Linux из корня проекта укажите в `PROOFREADER_TEST_DB_URL` адрес **одноразовой PostgreSQL с применёнными миграциями проекта**. Затем выполните:

```sh
PROOFREAD_ASSIST_BINARY="$PWD/volunteer/proofread-assist/dist/proofread-assist" \
  go test ./volunteer/proofread-assist/tests -run TestPackagedChapterReview -count=1 -v
```

Тест поднимает Go API и поддельный сервер модели, запускает помощник и проверяет в базе одно предложение модерации после повторной отправки.
