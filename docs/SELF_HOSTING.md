# Своя читальня

Как поднять читальню на своём сервере, под своим именем и со своим корпусом.
Код при этом не правится: всё, чем ваша читальня отличается от любой другой,
— переменные окружения и каталог экземпляра.

## 1. Попробовать локально

```bash
cp env.example .env
docker compose up --build
```

Читальня — http://localhost:3100, вход `admin@proofreader.local` / `admin`.
Загрузите пробную книгу ([CORPUS.md](CORPUS.md)), чтобы увидеть путь
целиком.

## 2. Настроить экземпляр

### Переменные окружения

В `.env` (локально) или в серверном `/opt/proofreader/app/.env`:

| Переменная | Что задаёт | Пусто |
|---|---|---|
| `SITE_NAME` | имя в шапке, подвале, вкладках, превью ссылок, OPDS, MCP, на титуле выгрузок | «Читальня» |
| `SITE_DESCRIPTION` | одна фраза о собрании: главная для поисковиков, подвал, справка, MCP | нейтральная фраза |
| `PUBLIC_BASE_URL` | адрес читальни, как его видит браузер (`https://lib.example.org`) | `http://localhost:3100` |
| `SITE_SUPPORT_URL` | ссылка «Поддержать читальню» в подвале и справке | нет ссылки и раздела |
| `SITE_CHANNEL_URL` | канал новостей в подвале | нет ссылки |
| `SITE_TAGLINE` | короткая подпись под именем в шапке | нет подписи |
| `SITE_AGE_RATING` | знак возрастной маркировки (`18+`) в подвале | нет знака |
| `RESERVED_NICKNAMES` | занятые ники через запятую — например, имена авторов корпуса | только служебные |

Имя читальни занято как ник всегда.

### Каталог экземпляра `instance/`

Каталог `instance/` в корне репозитория монтируется в контейнер фронтенда
(`docker-compose.yml`). nginx отдаёт файл отсюда раньше файла сборки,
поэтому сюда кладут:

- `favicon.svg`, `favicon.ico`, `apple-touch-icon.png`, `icon-192.png`,
  `icon-512.png`, `icon-maskable-512.png`, `site.webmanifest` — свой облик;
- файлы подтверждения поисковиков и ключ IndexNow;
- `legal.html` — страница `/legal` (HTML-фрагмент, его отдают как есть: якоря
  `id="…"` и почтовые ссылки работают). Нет файла — нет страницы и ссылки на
  неё; знак возрастной маркировки ведёт на `/legal#age`, если файл есть;
- `static-exclude.txt` — тома, которые не идут в статическую копию (пишет
  `scripts/takedown.sh`).

Правовой текст — ваш: платформа не делает за оператора юридических
утверждений о нём самом.

## 3. Сервер

Нужны свежая Ubuntu с root по SSH и домен, A-запись которого указывает на
сервер. Для хранилища на самом сервере нужен ещё поддомен `s3.<домен>`
(подпись presigned-ссылок включает хост, префикс пути её ломает).

Разворачивание идёт из снапшота: код приезжает внутри него
(`repo.bundle`), данные — тоже. Для новой читальни снимите снапшот с
локального стека (пусть даже пустого):

```bash
make docker-up && make migrate-up      # если стек ещё не поднят
./scripts/backup.sh                    # backups/proofreader-<UTC>/
./scripts/deploy.sh root@203.0.113.4 --domain lib.example.org \
    --acme-email you@example.org --snapshot latest
```

`deploy.sh` проверяет снапшот и DNS, везёт снапшот и `bootstrap.sh`, а дальше
работа идёт на сервере в tmux-сессии `proofreader-bootstrap` и переживает
обрыв связи (`ssh root@host tmux attach -t proofreader-bootstrap`). Фазы
отмечаются в `/opt/proofreader/state/`: повторный запуск продолжает с
упавшей. Секреты (`DB_PASSWORD`, `JWT_SECRET`, ключи S3, пароль
администратора) генерируются на сервере один раз; итоговые реквизиты — в
`/opt/proofreader/config/CREDENTIALS`.

Наружу смотрит только Caddy на 80/443 с сертификатом Let's Encrypt.

Флаги `deploy.sh`: `--domain` (обязателен), `--s3-domain`, `--acme-email`,
`--snapshot latest|<имя>|<путь>`, `--admin-password` (пароль администратора
из снапшота), `--force-restore` (восстановить заново), `--skip-dns-check`
(сервер за прокси), `--external-s3` (см. ниже).

Код приезжает из снапшота, поэтому `instance/` попадает на сервер, если он
закоммичен в вашем форке. Иначе положите файлы в
`/opt/proofreader/app/instance/` сами (`scp`), а переменные экземпляра
допишите в `/opt/proofreader/app/.env` и перезапустите стек
(`docker compose -f docker-compose.yml -f docker-compose.prod.yml up -d`).

## 4. Внешнее хранилище

Если диск сервера не вмещает сканы, храните их у S3-провайдера:

```bash
# в локальном .env
EXTERNAL_S3_ENDPOINT=https://s3.example.org
EXTERNAL_S3_REGION=default
EXTERNAL_S3_ACCESS_KEY=…
EXTERNAL_S3_SECRET_KEY=…
```

`deploy.sh --external-s3` не заводит поддомен `s3.`, не везёт файлы
снапшота и восстанавливает только базу. Режим определяется адресом в
`S3_ENDPOINT` серверного `.env`: местный SeaweedFS — пустой адрес,
`seaweedfs`, `localhost`, `127.0.0.1`; всё прочее — внешнее хранилище. При
внешнем хранилище `backup.sh`, `restore.sh`, `reset.sh` и
`verify-restore.sh` отказываются работать (их зеркалирование стёрло бы чужой
бакет) — бэкап сканов тогда делается средствами провайдера. CORS для записи
звука из браузера бэкенд ставит сам по `S3_CORS_ORIGINS`.

Заливать файлы в такие хранилища удобнее `mc mirror --disable-multipart`:
часть провайдеров на Ceph RGW отвергает multipart, который шлёт mc.

## 5. Бэкап и восстановление

```bash
./scripts/backup.sh               # база + бакет -> backups/proofreader-<UTC>/
./scripts/restore.sh latest       # восстановить (спросит подтверждение)
./scripts/verify-restore.sh       # бэкап -> одноразовое окружение -> сверка
```

Снапшот — `manifest.json`, `meta.tar` (дамп базы и `repo.bundle`) и
каталог `files/` (зеркало бакета). Хранятся три последних
(`BACKUP_KEEP`). `restore.sh` приводит бакет **точно** к снапшоту и
удаляет лишнее.

## 6. Обновление

```bash
./scripts/release.sh root@host --ref v1.2.0 [--with-backup] [--dry-run]
```

`release.sh` собирает образы локально (`docker build --platform
linux/amd64`), везёт их на сервер и применяет миграции; данные не трогает.
Собирать образы на маленьком сервере не стоит: два параллельных `docker
build` укладывают машину с 2 ядрами и 4 ГБ без свопа. Готовые образы
каждого тега лежат и в `ghcr.io/mx-weltanschauung/proofreader-*`.

## 7. Снятие материала

`scripts/takedown.sh` снимает том или его справочный аппарат одной командой
и дописывает том в `instance/static-exclude.txt`. Как пользоваться —
`scripts/takedown.sh` без аргументов. Для `--prod` нужен `PROD_API_URL` —
адрес живой читальни.
